# pm-ui-flow 使用说明

一个让 AI 以「较真的产品搭档」方式设计 UI 原型的技能：先建模、再问清字段来源、校验业务闭环，最后才画页面，并产出一份设计文档。

## 一、包里有什么

```
pm-ui-flow/                     ← 标准 Skill 目录，整个放进去
├── SKILL.md                    工作流与行为约束（入口文件）
├── references/
│   ├── closure-checklist.md    七类闭环检查项
│   ├── question-bank.md        提问与挑刺模板
│   └── design-doc-template.md  设计文档模板
├── assets/
│   ├── prototype-shell.html    列表/详情页骨架
│   ├── prototype-form.html     新建/编辑页骨架
│   └── prototype.css           后台风格样式
└── scripts/
    └── audit-prototype.mjs     原型审计脚本（可选，需 Node 18+）

pm-ui-flow-单文件版.md          给不支持 Skill 目录的工具用
使用说明.md                     本文件
```

## 二、装到别的软件里

### 方式 A：支持 Agent Skills 的工具（推荐）

这类工具会读取 `SKILL.md` 的 YAML 头（`name` + `description`），在合适的时候自动调用。

1. 解压 `pm-ui-flow-skill.zip`，得到 `pm-ui-flow/` 文件夹。
2. 把**整个文件夹**放进该工具的 skills 目录：
   - **Qoder**：用户级 `~/.qoder-cn/skills/`；项目级 `<项目>/.qoder/skills/`
   - **Claude Code**：用户级 `~/.claude/skills/`；项目级 `<项目>/.claude/skills/`
   - 其他工具：在设置里找 Skills / 技能 / Agent Skills，把文件夹放到它指定的目录
3. 重载技能或重启会话（Qoder 可执行 `/skills reload`）。
4. 直接提需求即可，例如：
   - 「帮我设计一个工单管理的后台，运营提交、主管审核」
   - 「出个采购申请的原型，要能新建、审核、查看」
   - 「这个流程怎么走：客户下单 → 发货 → 退货」

目录名必须和 `SKILL.md` 里的 `name` 一致，都叫 `pm-ui-flow`。不要只复制 `SKILL.md`，`references/`、`assets/`、`scripts/` 是它工作时要读的文件。

### 方式 B：不支持 Skill 的工具（ChatGPT / Claude 网页版 / Gemini 等）

用 `pm-ui-flow-单文件版.md`：

1. 打开该工具的自定义指令 / 系统提示 / 项目说明 / 规则文件。
2. 把单文件版**全文粘贴**进去，保存。
3. 直接提 UI 原型需求。

如果工具只能上传附件，也可以把单文件版作为知识文件上传，并在对话开头说一句：「按附件里的 PM UI Flow 规则工作」。

单文件版不依赖脚本，自检改为人工清单；生成多页面时如果不能写文件，会按「文件名 + 完整代码块」输出。

## 三、它会怎么工作

1. **先确认业务模型**：角色、实体、状态、动作。信息不够会先问你。
2. **字段溯源**：判不出是手填、系统生成、外部导入还是计算得出的字段，会停下来问，并给候选答案让你选。
3. **先给页面地图**，再生成多页面 HTML。
4. **三类问题分开处理**：
   - 硬伤（数据无处查看、页面没出口、状态没终态、角色没入口）→ 直接补最小方案，并告诉你补了什么；
   - 建议（能合并、能简化）→ 先问你要不要改；
   - 未知项（来源、规则不明）→ 不给猜，先问。
5. **产出**：`index.html` + `pages/*.html` + `assets/prototype.css` + `design-doc.md`。
6. **自检**：有 Node 环境时运行审计脚本，阻断级问题修完才交付。

交付说明固定五段：生成了什么 / 补了什么 / 想改什么 / 还需确认什么 / 自检结果。

## 四、审计脚本（可选）

需要 Node.js 18 或更高版本：

```bash
node pm-ui-flow/scripts/audit-prototype.mjs <原型目录>
```

- 退出码 `0`：无阻断问题；`1`：有阻断；`2`：路径错误。
- 检查内容：页面标记、断链、孤岛页、有新建无查看、表单字段无展示、保存跳转目标、返回出口、控件缺 name。
- 在 Windows 的 Git Bash / PowerShell / CMD 中都可以运行。

没有 Node 也不影响生成原型，只是少了机械校验，改由模型按单文件版里的 A–J 清单人工过。

## 五、常见问题

**装了但没被触发？**
确认目录名是 `pm-ui-flow`、`SKILL.md` 在文件夹根目录、YAML 头的 `name` 没改；然后重载技能/重启会话。描述里同时包含中英文触发词，中文需求「设计页面 / 出原型 / 补后台页」都能命中。

**换工具后引用文件报错？**
说明只复制了 `SKILL.md`。把整个 `pm-ui-flow/` 文件夹一起复制，保持内部相对路径不变。

**想改规则？**
直接改 `SKILL.md`。注意 `description` 必须是单行、不超过 1024 字符；它是唯一的触发依据，改完要重载。更细的检查项在 `references/` 里改，不要塞回 `SKILL.md` 以免过长。

**能用于真实开发吗？**
它产出的是静态可点击原型和设计文档，用来评审业务逻辑，不连接后端、不含真实数据。确认逻辑后再进入开发。
