# 闭环校验清单

生成页面前逐条过。每条给出「不通过的样子」，方便对照判断。

## 一、数据查看闭环

用户在新页面填了东西、点了保存，之后能在某个地方看到它。

- [ ] 每个有「新建」入口的实体，都存在列表页或详情页
- [ ] 列表页能用肉眼找到刚新增的那条（至少靠排序或高亮）
- [ ] 表单里出现的每个字段，都能在列表或详情里被看到
- [ ] 有导入/同步/生成功能时，导入结果有页面可查，不是只弹个 toast
- [ ] 有批量操作时，操作结果可追溯

反面：新建页有 12 个字段，列表只展示 3 个，剩下 9 个填了就丢了。

## 二、页面可达与出口

- [ ] 每一页都能从入口页面点到（不是只能靠手输 URL）
- [ ] 详情页有回列表的路
- [ ] 创建/编辑页有取消，取消后回到来处
- [ ] 弹窗/抽屉关闭后，底层页状态没有被重置
- [ ] 没有孤儿页面：写好了但没有任何入口

反面：从列表点进详情，详情页只能靠浏览器后退键回去。

## 三、状态流转闭环

- [ ] 每个状态的取值被穷举（枚举写清）
- [ ] 每个状态都有到达它的动作，也有离开它的动作
- [ ] 终态是明确的（完成/关闭/取消），不会永远悬着
- [ ] 状态改变会在页面上即时反馈到列表
- [ ] 不允许的动作有禁用理由，而不是点了没反应

反面：订单有「已取消」状态，但页面上找不到任何取消按钮，也没有谁能把订单变成取消。

## 四、角色权限闭环

- [ ] 每个角色至少有一个入口
- [ ] 每个页面对每个角色都有明确说明：可进入 / 不可见 / 只读
- [ ] 敏感操作（删除、审批、退款）绑定到具体角色
- [ ] 越权时给的是明确提示，不是空白页

反面：设计了「审核员」角色，但审核页在运营后台里，审核员进不去。

## 五、异常与空态

- [ ] 列表为空时有引导（去新建 / 去导入）
- [ ] 必填项缺失、格式错误有行内提示
- [ ] 提交失败有重试路径，且不丢已填内容
- [ ] 无权限、资源已删除、链接失效有兜底页
- [ ] 长文本、超大数字、空字段不会撑破布局

反面：校验失败后页面刷新，用户填的半小时内容全没了。

## 六、反向操作

- [ ] 删除有二次确认，且说明影响范围
- [ ] 删除后列表、统计、关联数据同步更新
- [ ] 审批可驳回，驳回有理由输入
- [ ] 可撤销的操作提供撤销入口；不可撤销的提前讲明
- [ ] 软删除的数据有查看或恢复入口（若业务需要）

反面：只能提交审核，不能撤回，提交错了只能等对方驳回。

## 七、入口与出口成对

逐个页面问一句：**从这里进来的人，事情做完之后去哪？**

- [ ] 新建 → 保存 → 列表并定位到新记录
- [ ] 详情 → 编辑 → 保存 → 回详情看到新值
- [ ] 状态操作 → 成功后回列表并提示结果
- [ ] 从仪表盘点进来的筛选条件，能被带进列表页
- [ ] 跨实体跳转（订单 → 客户）有回退路径

反面：从某客户的订单列表点进订单详情，想回客户只能重走一遍导航。

---

## 判定口径

| 情况 | 归类 |
| --- | --- |
| 数据产生了，但全站找不到查看它的地方 | 硬伤 |
| 页面存在但无入口，或进去后无出口 | 硬伤 |
| 状态有取值但无到达动作 | 硬伤 |
| 角色被设计出来但没有入口 | 硬伤 |
| 空态缺失、提示文案粗糙 | 建议 |
| 步骤可以合并、层级可以更浅 | 建议 |
| 字段来源不明 | 未知项（必须问） |
| 业务规则没定（如"什么条件下能取消"） | 未知项（必须问） |
