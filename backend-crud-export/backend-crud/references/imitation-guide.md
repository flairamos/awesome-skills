# 模仿与生成细则

## 一、侦察顺序

目标是找到"这个项目认为正确的写法"，不是找"网上的正确写法"。按下面顺序做**定向读取**，不要整仓扫描、不要通读大文件：

1. 路由注册文件：确认 URL 前缀、分组、中间件、权限挂载方式。
2. 最近修改的同类模块：handler → service → repository → model → dto → 测试。
3. 统一响应与错误定义：成功结构、错误码、错误包装、HTTP 状态码映射。
4. 分页/筛选/排序的公共结构或工具。
5. 数据库层：ORM 还是原生 SQL、事务怎么写、context 怎么传。
6. 迁移目录与 `docs/` 下现有 Postman collection。

参考模块只选一个主参照；出现两种风格时，选最近修改、覆盖场景更全的那个。两者冲突且影响接口形态时问用户。

## 二、项目约定卡

侦察完先写一张不超过 15 行的卡，后续按卡执行：

```
分层：handler / service / repository / model / dto
路由：/api/v1，group + JWT + RBAC 中间件
响应：{ code, message, data }，错误码在 pkg/errcode
分页：page/pageSize，返回 { list, total }
DB：GORM，事务用 db.Transaction，context 透传
校验：binding tag；业务校验在 service
日志：zap，字段 request_id/user_id
测试：同包 _test.go，testify + sqlmock
迁移：migrations/YYYYMMDD_name.sql
文档：docs/ 下按模块一个 collection
```

约定卡属于项目级长期信息，可以复用；只要业务结论，不抄代码。

## 三、参考模块怎么选

优先满足：同实体类型（主数据 / 单据 / 关系表）、同接口风格（REST / gRPC-gateway）、包含完整 CRUD 和测试、最近 3 个月有改动。

不要拿脚手架生成的空模块当参照；不要拿正在重构的分支当参照；不要跨项目抄风格。

## 四、model 解析（Go）

逐个字段确认：

| 结构体特征 | 生成时的处理 |
| --- | --- |
| `json:"name"` | 请求/响应字段名以它为准；`-` 表示不对外 |
| `binding:"required"` / `validate` | 转为请求校验；没有标签不擅自加必填 |
| 指针 `*T` | 可空；更新时区分"未传"与"置空" |
| `gorm:"primaryKey"` | 请求忽略；路径参数或服务端生成 |
| `gorm:"autoCreateTime"` | 服务端生成，响应只读 |
| `gorm:"index"` / `uniqueIndex` | 查询/冲突处理要利用；重复键要转成明确错误 |
| `gorm.DeletedAt` | 删除用软删除；查询依赖 ORM 默认作用域，原生 SQL 要手写 `deleted_at IS NULL` |
| `decimal` / 金额 | 按项目类型；禁止 float 做金额运算；序列化方式照抄 |
| `time.Time` | 时区与格式照项目；不要自创字符串时间 |
| 枚举/常量 | 校验取值；状态流转必须有到达动作 |
| 外键/关联 | 是否预加载看参考模块；列表禁止无界 Preload |
| 内嵌 struct | 按项目惯例展开或复用；不重复造字段 |
| 租户/组织字段 | 所有读写强制带条件；不能信任请求体里的 tenant_id |
| 版本号字段 | 更新带版本条件，处理并发冲突 |
| 未知 tag | 忽略，不猜含义；影响行为时问 |

**字段缺失就是阻断**：接口需要但 model 没有的字段，先问是加字段、从关联取，还是不做。不要伪造字段或悄悄改表。

## 五、CRUD 生成矩阵

| 接口 | 必须做 | 常见错误 |
| --- | --- | --- |
| 列表 | 分页、稳定排序、允许的筛选、租户/权限条件、上限 | 全表返回、排序字段可注入、总数与列表条件不一致 |
| 详情 | 按主键 + 权限/租户查、404 语义、敏感字段脱敏 | 只按 ID 查导致越权、把内部字段全量返回 |
| 创建 | 必填校验、唯一冲突、服务端字段忽略、事务、返回完整视图 | 接收客户端传来的 ID/状态/租户、重复提交 |
| 更新 | 全量或部分更新明确、可空字段处理、乐观锁、禁止 mass assignment | 零值覆盖、把 DTO 直接写回 model、越权更新 |
| 删除 | 软/硬删除明确、权限、二次确认语义、关联处理 | 无条件删除、物理删除有软删除的实体、删完列表统计不一致 |
| 状态操作 | 合法流转、幂等、事务、审计字段 | 任意状态互跳、重复提交产生副作用 |

只在用户要求的范围内生成；没有删除需求就不加删除接口。

## 六、分层写法

- **DTO**：请求与响应分开；不要把 model 直接当请求体。响应字段与 model 的对外字段一致，不额外编造。
- **repository**：只做数据访问；条件完整（主键 + 租户/权限）；错误向上返回，不吞。
- **service**：业务规则、状态流转、事务边界、外部调用编排；不直接拼 SQL。
- **handler**：参数绑定、校验、调用 service、统一响应；不写业务规则。
- **route**：按现有分组注册；鉴权中间件与权限点照抄。
- **测试**：照参考模块；至少覆盖成功、参数错误、无权限/不存在、关键状态冲突。

多表写入、状态变更 + 明细写入、扣减/回滚必须在同一事务；外部调用不要长时间占着事务。

## 七、正确性检查

- 越权：所有按 ID 的读写是否同时校验租户/归属/权限。
- 注入：排序字段、表名、LIKE、IN 拼接是否白名单或参数化。
- 空值与零值：更新时能否区分"没传"和"传了 0/空串"。
- 分页：page/pageSize 边界、最大页大小、total 与数据一致性。
- 并发：重复提交、并发更新、库存扣减是否需要锁/版本号/幂等键。
- 软删除：唯一索引与软删除的冲突；原生 SQL 是否漏了 `deleted_at IS NULL`。
- 时间与金额：时区、精度、序列化；禁止 float 金额。
- 敏感信息：响应、日志、错误信息里是否带密码/token/密钥。
- 错误语义：404/409/422 是否与项目一致；不要把数据库错误原样抛给调用方。

## 八、模仿的边界

模仿的是**结构与风格**，不是缺陷。参考模块里出现下列问题时，不要照抄，按 P0/P1 上报：

- 无条件删改、SQL 拼接、越权查询
- 事务缺失、错误被吞、请求路径 panic
- 无上限列表、明显 N+1、无 context 超时
- 密钥硬编码、敏感字段直接返回

除此之外，不因个人偏好改命名、改目录、换库、换写法。

## 九、其他技术栈

Java/Spring：Controller → Service → Mapper/Repository → Entity，参照现有 VO/DTO、`@Valid`、统一 `Result`、MyBatis/JPA 写法。
其他语言同理：先定位等价分层与统一响应，再按本指南的字段与正确性规则生成。不要混用两套风格。
