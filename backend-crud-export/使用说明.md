# backend-crud 使用说明

一个按项目原有风格生成后端 CRUD 的技能：先侦察同类模块、按 model 结构体生成代码，同时约束上下文、缺陷上报、SQL 安全和接口文档。

## 一、包里有什么

```
backend-crud/                    ← 标准 Skill 目录，整个放进去
├── SKILL.md                     工作流与硬规则（入口文件）
├── references/
│   ├── imitation-guide.md       侦察、参考模块、model 解析与 CRUD 生成细则
│   ├── context-and-defects.md   业务卡片、缺陷分级、注释规则
│   └── postman-standard.md      Postman Collection v2.1 规范
├── assets/
│   └── postman-collection-template.json   可直接改写的文档模板
└── scripts/
    ├── sql-guard.mjs            SQL 安全守卫
    └── validate-postman.mjs     Postman 文档校验

backend-crud-单文件版.md         给不支持 Skill 目录的工具用
使用说明.md                      本文件
```

## 二、装到别的软件里

### 方式 A：支持 Agent Skills 的工具（推荐）

这类工具会读取 `SKILL.md` 的 YAML 头（`name` + `description`），在合适的时候自动调用。

1. 解压 `backend-crud-skill.zip`，得到 `backend-crud/` 文件夹。
2. 把**整个文件夹**放进该工具的 skills 目录：
   - **Qoder**：用户级 `~/.qoder-cn/skills/`；项目级 `<项目>/.qoder/skills/`
   - **Claude Code**：用户级 `~/.claude/skills/`；项目级 `<项目>/.claude/skills/`
   - 其他工具：在设置里找 Skills / 技能 / Agent Skills，放入它指定的目录
3. 重载技能或重启会话（Qoder 可执行 `/skills reload`）。
4. 在**具体项目目录**里提需求，例如：
   - 「参照 order 模块，按 User model 生成一套 CRUD」
   - 「新增退款单接口，按现有分层和响应格式来」
   - 「审查这次订单模块改动，有严重问题直接说」

目录名必须和 `SKILL.md` 里的 `name` 一致，都叫 `backend-crud`。不要只复制 `SKILL.md`，`references/`、`assets/`、`scripts/` 是它工作时要读的文件。

### 方式 B：不支持 Skill 的工具（ChatGPT / Claude 网页版 / Gemini 等）

用 `backend-crud-单文件版.md`：

1. 打开该工具的自定义指令 / 系统提示 / 项目说明 / 规则文件。
2. 把单文件版**全文粘贴**进去，保存。
3. 直接提需求。它能读写文件时按路径生成代码；不能写文件时按「文件路径 + 完整代码块」输出。

如果工具只能上传附件，也可以把单文件版作为知识文件上传，并在对话开头说一句：「按附件里的 Backend CRUD 规则工作」。

单文件版不依赖脚本，SQL 检查和 Postman 检查改为内置的人工清单。

## 三、它会怎么工作

1. **侦察**：先找同类参考模块，产出项目约定卡（分层、路由、响应、错误码、分页、事务、测试），不贴代码。
2. **模型优先**：读 model 结构体，输出业务卡片；字段来源不明、缺字段、删除语义不清会先问你。
3. **模仿生成**：按 DTO → repository → service → handler → route → 测试的顺序，照项目风格生成；不擅自加依赖、不改无关代码。
4. **缺陷上报**：P0（越权、注入、无 WHERE 删改、事务缺失、密钥泄露等）立即报；P1 当前步骤结束前最多 3 条；已修复的不归档、不重复提。
5. **上下文只留业务**：只保留业务卡片，不保留代码、diff、堆栈、缺陷明细；恢复时按路径重读代码。
6. **SQL 安全**：执行前过守卫，拦截无条件 DELETE/UPDATE、恒真 WHERE、TRUNCATE、DROP、ALTER DROP。
7. **接口文档**：新模块完成时在项目 `docs/` 生成或追加 Postman Collection v2.1。
8. **交付**：业务卡片、改动路径、验证结果、文档路径、未解决的严重缺陷和待确认问题。

## 四、两个脚本（可选）

需要 Node.js 18 或更高版本。

### SQL 守卫

```bash
node backend-crud/scripts/sql-guard.mjs --sql "DELETE FROM orders WHERE id = ?"
node backend-crud/scripts/sql-guard.mjs --file migrations/20261022_cleanup.sql
node backend-crud/scripts/sql-guard.mjs --scan .
```

- 退出码 `0`：安全；`1`：拦截；`2`：参数或路径错误。
- 拦截：无顶层 WHERE 的 DELETE/UPDATE、`WHERE 1=1`/`true`、TRUNCATE、DROP TABLE/DATABASE/SCHEMA、ALTER TABLE ... DROP。
- 注释、字符串、子查询里的 WHERE 不会被误认为有效条件。
- `--scan` 只扫描 `.sql` 文件；写在 Go/Java 代码里的 SQL 用 `--sql` 单独检查。
- 它是保守的词法检查，不解析存储过程/触发器内部逻辑；这类对象要人工复核。
- 合法但有破坏性的迁移也会被拦截，这是有意的：先备份、说明影响，再由用户明确确认。

### Postman 校验

```bash
node backend-crud/scripts/validate-postman.mjs docs/order.postman_collection.json
```

- 退出码 `0`：无错误；`1`：有错误；`2`：文件或参数错误。
- 检查 schema 版本、名称、method、URL、重复请求名、明文 token、未定义变量、示例响应、JSON body 是否可解析。
- 输出里的 warning 需要人工判断，不一定要改。

## 五、常见问题

**装了但没被触发？**
确认目录名是 `backend-crud`、`SKILL.md` 在文件夹根目录、YAML 头的 `name` 没改；然后重载技能/重启会话。描述里同时包含中英文触发词，中文需求「按 model 生成 CRUD / 新增接口 / 审查后端改动 / 补接口文档」都能命中。

**换工具后引用文件报错？**
说明只复制了 `SKILL.md`。把整个 `backend-crud/` 文件夹一起复制，保持内部相对路径不变。

**生成时会不会自己加字段？**
不会。model 是契约；接口需要但 model 没有的字段，它会先问是加字段、从关联取，还是不做。需要改表时会先说明字段、类型、默认值、索引和回填方案。

**上下文真的会忘掉代码吗？**
模型无法物理删除已读入的 token。它约束的是：不把代码、diff、堆栈、缺陷明细写进业务卡片，不在摘要和交付里复述；业务卡片是唯一的长期记录，需要细节时重新读文件。

**能用于 Java / 其他后端吗？**
可以。它会先找等价分层（Controller/Service/Mapper/Entity）和统一响应，再按同一套字段、事务、安全规则生成；Go 的 model 解析细则最完整。

**纯 gRPC 模块会生成 Postman 吗？**
只有存在 HTTP gateway / grpc-gateway 映射时才生成，并且只收录实际暴露的 HTTP 路由；纯 gRPC 会先问你改用哪种文档形式。

**想改规则？**
直接改 `SKILL.md`。注意 `description` 必须是单行、不超过 1024 字符；它是唯一的触发依据，改完要重载。更细的规则放 `references/`，不要全塞回 `SKILL.md`。

**能用于生产吗？**
它只生成和审查代码、写文档，不执行生产命令、不读取真实密钥。所有 SQL 执行前仍应走守卫和人工确认。
